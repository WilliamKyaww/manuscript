# Backlog

Structured, not a dumping ground. Three files:

| File | Contains | ID format |
|---|---|---|
| [backlog.md](./backlog.md) | Future features, ideas, improvements, deferred work | `B-<area>-NN` (areas: KM knowledge, LE learning, AI, PL platform) |
| [technical-debt.md](./technical-debt.md) | Known shortcuts and their repayment plan | `TD-NN` |
| [research-questions.md](./research-questions.md) | Open questions for the user or for further research | `RQ-NN` |

Rules:
1. Every item has a one-line *why* (the user value or risk) and, if deferred from a phase, the phase.
2. Items are promoted into a phase checklist when scheduled; the backlog entry then links to the task.
3. Rejected ideas are recorded in `FEATURES.md` → *Rejected* (with the reason), not here.
4. Review the backlog at every phase gate: close, promote or re-justify items.
