and a permission allowlist limited to full screen and clipboard writes. The application session and its token
are separate. New-tab links stay in the pane; explicit popup windows share the web session. Native views hide
behind a snapshot for covering application overlays, and are released with their tabs/owner.

## Implementation and decisions

ADR-0046 records the right-side placement requirement and the browsing-feedback contract. The workspace keeps
its two-pane architecture and remains responsible for ordering; bounds continue to follow the actual DOM host.
`openWebPage` now commits `[from, updated]` for an existing other pane, or `[from, created]` for a new one, sets
the split to `right` and leaves `from.id` active. Existing other-pane tabs are retained, and an already-open URL
is selected instead of duplicated. On loading saved state, only an unambiguous web-only first pane beside a
note-only second pane is reversed. Mixed tab collections and note-only splits are not rearranged on restore;
opening a new web link still puts its source pane first. This avoids guessing about the student's mixed layout.

The browser work removes existing user-agent token stripping and uses Electron's normal identity. It does not
forge another browser's identity or transfer verification cookies. Browser state gains
`issue: { kind: 'http' | 'load' | 'crash', code } | null`, propagated through the existing preload bridge.
HTTP errors retain their response HTML and interactions, because a 403 can carry a legitimate verification form;
transport failure and crashes receive clear feedback with the requested URL retained for retry or the existing
external-browser action. No broader permissions or weaker web-security settings are authorised or needed.

`watchWebLoad` tracks main-frame navigation, redirects, HTTP statuses and renderer crashes. It ignores aborted,
superseded and child-frame failures, and keeps HTTP diagnostics through same-document navigation. Only a kind
and numeric code cross IPC; no response body, headers, cookies or challenge identifiers are sent to the app.
`WebPageNotice` sits above the measured host. HTTP responses remain native and interactive; load/crash states
hide the unusable view. **Try again** loads the retained address, and **Open in system browser** uses the existing
validated OS handoff. Successful navigation clears the notice. No CSS reversal or independent native-coordinate
override is needed for placement.

## Problems encountered

- The default shell/login tool invocation initially stalled; explicit PowerShell with `login: false` worked.
  UTF-8 reads are needed for British punctuation, and edits use the patch tool to avoid PowerShell encoding issues.
- Original code did not send load-failure details to the renderer; swallowing `loadURL` rejection left no
  useful explanation for a blank native page. That is a separate confirmed feedback defect from the publisher's
  decision to serve a 403.
- The tool sandbox denied esbuild an ancestor-directory read and prevented Electron's sandboxed children from
  reading its distribution. The same commands passed through approved execution outside the tool sandbox;
  Electron's own sandbox stayed enabled and test profiles/vaults stayed isolated.
- Test development caught two TypeScript errors, formatting and an unsafe optional chain; corrected before
  final checks. The first component run lacked Radix's Tooltip provider; corrected before the meaningful red run.
- Early Electron assertions used an obsolete note-tab selector (creation replaces the active note tab; the
  file-tree item is the navigation target) and assumed the first window remained the app after a popup.
  Tests now identify the owning window. Native Return activation needed focus restored after closing the popup
  and a character event; this was a test-input defect, not a change to browser security or page scripts.
- Native screenshot capture can precede repaint after theme changes. Theme tests now use media emulation,
  reduced motion and settled frames. Non-failing existing warnings: happy-dom deliberately blocks embedded PDF
  iframe loading, Vite reports large chunks, and Playwright reports conflicting colour-output environment flags.
