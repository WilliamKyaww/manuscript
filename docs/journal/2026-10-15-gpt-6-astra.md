## Implementation in progress

`apps/desktop/src/browser-views.ts` preserves the existing preload contract and selects WebView2 on
Windows, with Electron retained as the unavailable-runtime/other-platform fallback. The new
`webview2-client.ts`, `webview2-protocol.ts` and `webview2-views.ts` manage private pipes, validated
messages, native child-window bounds, visibility, snapshots, lifecycle and failure recovery.
`apps/desktop/native/WebPane/` contains a .NET Framework helper using Microsoft's WebView2 Core SDK.
It creates child surfaces inside the Electron window, uses a separate persistent profile and exposes no
host objects, web messages, Node or application preload to websites. No browser identity or verification
tokens are changed. No security flags are disabled.

`scripts/build-webview2.mjs` verifies the pinned SDK archive checksum, builds the helper and copies its
BSD licence. Desktop build/packaging scripts and electron-builder resources include it outside the app
archive. The production helper uses .NET Framework, not the .NET 9 runtime used by the initial probe.

## Claude implementation map and latest validation

The full `npm run verify` subsequently completed successfully, including build and smoke. After removing
the unused TCP debugger option, type-check and repository Biome check passed again. The debug endpoint
experiment was abandoned: tests now set `SKB_WEBVIEW2_DIAGNOSTICS=1` (and `SKB_DEVTOOLS=1` for packaged
tests) to use `CoreWebView2.CallDevToolsProtocolMethodAsync` over the existing private pipe. There is no
listening debug port, DevTools UI remains disabled, and no diagnostic operation is reachable from the
renderer/preload. The normal app never enables this test option.

- `BrowserViews` selects and routes engines, retaining the existing `web` preload contract. Automatic
  initialisation failure falls back to Electron; explicit `SKB_BROWSER_ENGINE=electron` supports regressions.
- `WebView2Client` starts the helper with its own profile and parent PID, validates replies, limits buffers
  and pending requests, handles timeout/crash and closes through stdin EOF with a bounded kill fallback.
- `WebView2Views` tracks unique native keys per tab generation, latest bounds during startup, cover/minimise
  visibility, renderer state, bounded retained tabs and crash retry. `inspect()` is process-internal only.
- Native `Surface.cs` owns/clips the child HWND and accounts for Windows DPI. `BrowserPage.cs` maps response,
  history, navigation and process events, snapshots and popup requests. `Popup.cs` shares only the web profile.
  `Program.cs` serialises commands and owns a hidden blank controller to preserve session cookies between
  closing/reopening tabs. Parent exit and pipe closure shut the helper down.
- `scripts/build-webview2.mjs`, `build-desktop.mjs`, `pack-desktop.mjs` and `electron-builder.yml` include the
  helper and SDK licence in unpacked/installer resources. SDK archive digest is pinned; only the required
  Core assembly and x64 loader are extracted. `THIRD_PARTY_NOTICES.md` records BSD-3-Clause licensing.
- Package/lock changes are only direct `zod` declaration for desktop IPC validation and build-time `fflate`
  declaration; both versions already exist in the repository. No Electron upgrade was retained.

The formerly failing close/reopen test now passes with the hidden session controller. The extended local
native test also passes popup creation, same-session popup storage and absence of Node/application bridge.
The equivalent Electron response/popup test still passes. `desktop:build` succeeded with the new helper.
